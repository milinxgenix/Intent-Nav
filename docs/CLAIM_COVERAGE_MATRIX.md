- **`INTEGRATION_TESTED`**: Full multi-module pipeline execution across the state machine and invariant closure.
- **`BROWSER_E2E_TESTED`**: Verified in live Google Chrome via Chrome DevTools Protocol (CDP) and extension runtime.
- **`EMPIRICALLY_VERIFIED`**: Validated across live mock sites in Google Chrome and comparative benchmark trials.

## Verification Level Notes

> [!NOTE]
> **REQ-C13 (Non-Silent Fallback) and REQ-C14 (Risk Gate)** are verified at `BROWSER_E2E_TESTED` following successful execution and validation of the negative Chromium E2E scenarios (N1–N14 via `npm run test:e2e:chromium:neg` and `npm run validate:evidence:neg`). All 14 adversarial conditions refused execution with zero safety bypasses.

> [!IMPORTANT]
> **REQ-C18** is listed as `INTEGRATION_TESTED`. The "2,000 runs" figure comes from the CONTROLLED SIMULATED BENCHMARK (JSDOM, `benchmark/runner.ts`) — NOT from real Chrome. Do not interpret this as empirical browser evidence. The claim's core mechanism (quorum gating) is unit and integration tested.

> [!NOTE]
> **EMPIRICALLY_VERIFIED** means: demonstrated in live Google Chrome via CDP, with the specific scenario captured in `evidence/chromium_e2e_evidence.json` and independently validated by `scripts/validateChromiumEvidence.js`. Claims marked `BROWSER_E2E_TESTED` are exercised in Chrome but not specifically the focus of a dedicated quantitative validation pass.
